# DNS 中继服务器课程设计解读与开发指引

本文基于 `docs/计算机网络课程设计-2025.pptx` 提炼实验说明和验收要求；`dnsrelay.txt`、RFC1034/RFC1035 和两个 DNS 字段说明 txt 只作为协议实现参考。

## 1. 这个实验要做什么

指定题目是实现一个 DNS 中继服务器程序。程序本质上是一个运行在本机或局域网某台机器上的 DNS Server：客户端把 DNS 服务器地址配置为你的程序所在地址，客户端发出的 DNS 查询先到你的程序，再由你的程序决定本地回答、拦截，或转发给真正的外部 DNS 服务器。

核心输入是一个“域名 - IP 地址”对照表文件，PPT 中默认文件名为 `dnsrelay.txt`。当客户端查询域名对应的 IP 地址时，程序按查询域名检索该表，并得到三种结果：

1. 表中命中，且 IP 是 `0.0.0.0`：向客户端返回“域名不存在”的 DNS 错误响应，用于实现不良网站拦截功能。
2. 表中命中，且 IP 是普通 IPv4 地址：直接向客户端返回该 A 记录，实现一个简单 DNS 服务器功能。
3. 表中没有该域名：把原查询转发给外部 Internet DNS 服务器，收到外部响应后再返回给原客户端，实现 DNS 中继功能。

实验的难点不在界面，而在网络协议细节：UDP 收发、DNS 报文解析与构造、网络字节序、多客户端并发、ID 转换、超时和迟到响应处理。

## 2. PPTX 中的明确要求

### 功能要求

- 读取 `域名-IP地址` 对照表文件。
- 查询命中 `0.0.0.0` 时返回“域名不存在”的报错消息，即 DNS 响应码应体现 name error / NXDOMAIN。
- 查询命中普通 IP 时直接返回该地址。
- 查询未命中时向外部 DNS 服务器发出查询，并把结果返回给客户端。
- 允许多个客户端并发查询：第一个查询尚未得到答案时，也能继续处理后续查询。
- 并发中必须考虑 DNS 报文 Header 里的 `ID` 字段转换：转发给外部 DNS 时不能简单复用所有客户端原始 ID，否则不同客户端、不同请求可能冲突。
- 必须考虑 UDP 不可靠导致的超时、无应答、迟到应答。

### 环境与语言约束

- 操作系统可用 Windows、Ubuntu 等。
- 编程语言要求 C。
- 只可使用 C 标准库和 Socket 库；类似 LRU、字典、哈希表等数据结构如果需要，要自己实现。
- UDP 接收/发送使用 `recvfrom` / `sendto`。
- 注意网络字节序：网络序是 Big Endian，x86 常见主机序是 Little Endian，需要使用 `htons`、`ntohs`、`htonl`、`ntohl`。

### 推荐命令行形式

PPT 给了一个参考实现命令语法：

- `dnsrelay [-d | -dd] [dns-server-ipaddr] [filename]`
- 不带参数：无调试输出，外部 DNS 默认 `202.106.0.20`，配置文件默认当前目录 `dnsrelay.txt`。
- `-d`：调试级别 1，输出时间坐标、序号、客户端 IP、查询域名等。
- `-dd`：调试级别 2，输出更详细调试信息。
- 可指定外部 DNS 服务器 IP 和域名表文件。

### 运行和演示要求

Windows 演示流程大致是：

1. 用 `ipconfig /all` 记录当前 DNS 服务器地址，例如 `202.106.0.20`。
2. 把本机 DNS 设置为 `127.0.0.1`。
3. 运行 `dnsrelay`，程序内部把外部 DNS 设置为前面记录的服务器。
4. 用 `ping`、FTP、浏览器、`nslookup www.bupt.edu.cn` 等验证域名解析是否正常。
5. 局域网其它机器也可以把 DNS 指向你的中继服务器 IP，验证跨机器客户端访问。
6. 可用 `ipconfig /displaydns` 查看缓存，用 `ipconfig /flushdns` 清除系统 DNS 缓存。
7. PPT 备注提到必要时禁用 IPv6，避免系统走 IPv6 DNS 路径而绕过你的 IPv4 DNS 中继程序。

Linux/Ubuntu 下实际调试时，53 端口通常需要管理员权限。开发阶段可先绑定非 53 端口做自测，正式演示再按要求绑定 53 端口。

## 3. DNS 协议实现要点

PPT 的 DNS 简介部分和备注给出了实现必须理解的报文结构。

DNS 报文由五部分组成：

1. Header：固定 12 字节。
2. Question：查询问题。
3. Answer：回答资源记录。
4. Authority：权威资源记录。
5. Additional：附加资源记录。

最小可行版本主要处理 Header 和 Question，并在本地命中时构造 Answer；中继时可以转发整个原始报文，但要改写 ID 并维护映射关系。

Header 关键字段：

- `ID`：16 位事务 ID，由客户端设置，服务器响应时返回。中继程序必须用它匹配请求和响应。
- `QR`：0 表示查询，1 表示响应。
- `OPCODE`：通常为 0，即标准查询。
- `AA`：权威应答。
- `TC`：截断标志，UDP DNS 超过 512 字节可能截断。
- `RD`：客户端期望递归查询。
- `RA`：服务器支持递归查询。
- `Z`：保留字段，应为 0。
- `RCODE`：响应码，0 表示无错误，3 表示域名不存在。
- `QDCOUNT`、`ANCOUNT`、`NSCOUNT`、`ARCOUNT`：分别是 Question、Answer、Authority、Additional 数量。

Question 关键字段：

- `QNAME`：域名编码，不是普通字符串。格式是 `长度 + 标签 + 长度 + 标签 + ... + 0`，例如 `www.bupt.edu.cn` 会按每段标签分别编码，点号本身不出现在报文中。
- `QTYPE`：查询类型。最低要求建议优先支持 A 记录，也就是 IPv4 地址，类型值 1。
- `QCLASS`：查询类，通常是 IN，值 1。

Resource Record 关键字段：

- `NAME`：资源记录所属名字，可以使用压缩指针，例如指向 Question 里的 QNAME。
- `TYPE`：资源记录类型，A 记录为 1。
- `CLASS`：通常为 IN，值 1。
- `TTL`：缓存时间。
- `RDLENGTH`：RDATA 长度。A 记录固定为 4。
- `RDATA`：资源数据。A 记录中就是 4 字节 IPv4 地址。

## 4. `docs` 目录中其它材料的作用

- `dnsrelay.txt`：默认域名表样例。前半部分有大量 `0.0.0.0 域名`，用于拦截测试；也有普通 IP 映射，例如 `123.127.134.10 www.bupt.cn`。文件里存在大小写不同的重复域名，说明查表时应把域名统一转小写，因为 DNS 名字匹配通常不区分大小写。

- `DNS协议中资源记录的Type（类型）和Class（类）.txt`：常见 Type/Class 值速查，尤其是 A、NS、CNAME、MX、AAAA、PTR、IN。
- `RFC1034.TXT`：DNS 概念和递归/缓存/资源记录背景。
- `RFC1035-new.txt`：DNS 报文格式、Header、Question、RR、压缩指针、UDP 传输等实现规范。
- `实验报告模板.docx`：报告封面和附页模板。

## 5. 一个可行的 C 程序架构

下面是面向课程设计的保守架构，不生成代码，只说明模块边界。

### 总体流程

程序启动后解析命令行参数，加载域名表，初始化 UDP Socket，绑定本地 DNS 服务端口，进入事件循环。每次收到 UDP 报文后，先判断来源：如果来自外部 DNS 服务器，就按中继 ID 表找回原客户端并转发响应；如果来自客户端，就解析 DNS 查询，查本地域名表，命中则本地构造响应，未命中则改写 ID 后转发到外部 DNS。

### 模块划分

#### `main / config`

职责：

- 解析 `[-d|-dd] [dns-server-ipaddr] [filename]`。
- 设置默认外部 DNS 和默认配置文件。
- 初始化平台相关 Socket 环境，例如 Windows 下的 Winsock。
- 创建服务 Socket，进入主事件循环。
- 负责程序退出时释放资源。

#### `hosts_table`

职责：

- 读取 `dnsrelay.txt`。
- 解析每行 `IP 域名`。
- 校验 IPv4 地址格式。
- 将域名统一转小写并存储。
- 提供 `lookup(domain)`，返回三类结果：未命中、命中拦截、命中普通 IP。

实现建议：

- 初版可用动态数组 + 线性查找，容易完成且足够演示。
- 如果想体现性能，可自己实现简单哈希表，但不要一开始就把复杂度放在这里。

#### `dns_packet`

职责：

- 从原始 UDP 字节流中读取 DNS Header。
- 解析第一个 Question，拿到 QNAME、QTYPE、QCLASS。
- 将 DNS 编码域名转换为普通点分域名。
- 构造本地 A 记录响应。
- 构造 NXDOMAIN 响应。
- 提供读写 ID、Flags、计数字段的工具函数。

实现建议：

- 所有多字节字段都用网络字节序处理。
- 对报文长度做边界检查，防止越界读写。
- 第一版只承诺标准查询、`QDCOUNT=1`、`QTYPE=A`、`QCLASS=IN`。
- 非 A 查询可以直接中继给外部 DNS，避免自己实现所有 RR 类型。

#### `relay_state`

职责：

- 维护“转发 ID -> 原始请求”的映射。
- 每条记录保存：转发给外部 DNS 使用的新 ID、客户端原始 ID、客户端 IP 和端口、请求发出时间、是否占用。
- 生成当前未占用的新 ID。
- 收到外部响应时，根据响应 ID 查找记录，把响应 ID 改回客户端原始 ID，然后发回原客户端。
- 周期性清理超时记录。

实现建议：

- 因为 DNS ID 是 16 位，可用固定数组或开放寻址表保存 pending 请求。
- 超时时间可以先设为 3 到 5 秒。
- 收到迟到响应时，如果映射已清理，就丢弃并在调试日志中记录。

#### `net_loop`

职责：

- 管理 UDP 收发。
- 同时处理客户端请求和外部 DNS 响应。
- 实现并发：不能在等待某个外部 DNS 响应时阻塞整个程序。

实现建议：

- 单线程事件循环 + `select` 是最适合课程设计的方案：结构清晰，避免多线程共享数据带来的调试负担。
- 可用一个 UDP Socket 绑定本地服务端口，同时向外部 DNS 发送查询；也可拆成客户端监听 Socket 和外部转发 Socket。拆成两个 Socket 更容易区分来源。
- 每轮事件循环都检查超时 pending 表。

#### `logger`

职责：

- 根据调试等级输出信息。
- `-d` 输出时间、请求序号、客户端 IP、查询域名、处理结果。
- `-dd` 额外输出 ID 转换、外部 DNS 往返、超时、报文字段摘要。

### 推荐数据流

客户端查询路径：

1. 客户端向本程序发 UDP DNS 查询。
2. 程序解析 Header 和 Question，得到原始 ID、域名、QTYPE/QCLASS。
3. 查 `hosts_table`。
4. 如果命中 `0.0.0.0`，构造 `QR=1`、`RCODE=3`、`ANCOUNT=0` 的响应，ID 保持客户端原始 ID。
5. 如果命中普通 IP，构造 `QR=1`、`RCODE=0`、`ANCOUNT=1` 的 A 记录响应，ID 保持客户端原始 ID。
6. 如果未命中，向 `relay_state` 申请新 ID，改写原报文 ID，转发给外部 DNS。

外部响应路径：

1. 外部 DNS 返回响应。
2. 程序读取响应 ID，在 `relay_state` 中查找。
3. 找到后把响应 ID 改回客户端原始 ID。
4. 用保存的客户端 IP 和端口把响应发回去。
5. 删除 pending 记录。
6. 如果没找到，视为迟到或未知响应，丢弃。

## 6. 开发顺序建议

1. 先做命令行解析、Socket 初始化和简单 UDP 收发，确认程序能收客户端 DNS 查询。
2. 做 DNS Header 和 Question 解析，只打印域名、QTYPE、ID。
3. 做 `dnsrelay.txt` 加载和查表，先用线性查找即可。
4. 做本地普通 IP 响应，优先通过 `nslookup` 验证。
5. 做 `0.0.0.0` 拦截响应，验证能返回域名不存在。
6. 做未命中中继，先单请求跑通。
7. 加入 ID 转换表，验证多个查询同时发起时不会串包。
8. 加入超时清理和迟到响应丢弃。
9. 完善 `-d`、`-dd` 日志，准备现场演示和报告截图。

## 7. 测试建议

基本测试：

- 查表命中普通 IP：例如用表中已有的 `www.bupt.cn` 或自己添加一个测试域名。
- 查表命中 `0.0.0.0`：验证返回 NXDOMAIN 或等价的“域名不存在”响应。
- 查表未命中：验证能从外部 DNS 得到真实解析结果。
- 大小写域名：验证 `WWW.xxx.COM` 和 `www.xxx.com` 行为一致。
- 非 A 查询：验证不会错误构造 A 响应，建议直接中继。

并发测试：

- 连续快速发起多个 `nslookup`。
- 从两台机器同时把 DNS 指向中继服务器。
- 人为延迟外部 DNS 响应或换成不可达 DNS，观察超时清理。
- 用 Wireshark 看客户端 ID、转发 ID、返回 ID 是否符合设计。

验收演示测试：

- 展示本地服务器功能：表内普通 IP 返回。
- 展示拦截功能：`0.0.0.0` 返回不存在。
- 展示中继功能：表外域名仍可正常解析。
- 展示并发和 ID 转换：日志中能看到多个 pending 请求对应不同转发 ID。
- 展示超时处理：外部 DNS 不可达时程序不会卡死。

## 9. 最小可行版本与加分方向

最小可行版本：

- C 语言。
- UDP DNS Server。
- 读取 `dnsrelay.txt`。
- 支持 A 查询。
- 支持 `0.0.0.0` 拦截。
- 支持普通 IP 本地回答。
- 支持表外中继。
- 支持 ID 转换。
- 支持超时丢弃。
- 有 `-d` / `-dd` 基本日志。

稳妥增强方向：

- 更完整的错误处理和边界检查。
- 自己实现哈希表提升查表效率。
- 支持配置 TTL。
- 支持将非 A 查询透明中继。
- 日志中输出报文 ID、域名、QTYPE、处理路径、耗时。
- 用 Wireshark 截图作为报告证据。

不建议一开始做的方向：

- 图形界面。
- 完整实现所有 DNS RR 类型。
- 多线程版本。
- 复杂缓存策略或 LRU。PPT 明确说若需要 LRU/字典要自己实现，容易增加调试风险；等核心功能稳定后再考虑。
